# 本地模型：生命周期、档位选择与 AI 辅助

本文覆盖三件事：本地模型服务在本机怎么活、五个档位什么时候用哪个、以及十三个「一次性 AI 辅助」（体检解读 / 回忆与旅行起名 / 影院文件名兜底 / 分享文案 / 关键词补全 / 搜索改写 / 电视清洗 / 帮助问答 / 日志摘要 / 关键词归一化 / 地点补全 / 今晚看什么 / 影院系列归组）的开启规则与发送内容。

配置文件：`Resources/Models/local-llm.json`（打包后位于 `Luma.app/Contents/Resources/Models/`）。改它不需要重新编译。

---

## 1. 服务生命周期

本地模型服务（Ollama）跟着 Luma 走，不是常驻后台服务。

| 场景 | 行为 | 代码 |
|---|---|---|
| 打开「设置 › 本地模型」开关 | 下载运行时 → 解压到 `~/Library/Application Support/Luma/Models/Runtime/ollama` → 启动 `ollama serve`（仅监听 `127.0.0.1:11434`）→ 下载并注册模型 → 自动把提供商 / 地址 / 模型名接进助手配置 | `LocalLLMRuntime.enable()` |
| 关掉开关 | 停掉服务；**不删任何文件**，随时能再开 | `disable()` |
| 退出 Luma | 停掉服务，模型文件保留 | `applicationWillTerminate` → `shutdown()` |
| 重新打开 Luma | 启动时自动拉起服务并重新接好助手配置；本地档位比清单旧时顺手升级运行时；已装模型参数不对（例如旧版本按 4096 注册）会自动重建参数，不重下模型 | `LumaApp.init` → `refresh()` |
| 服务被意外关掉 / 崩溃 | 助手底栏显示「服务未启动 · 点此启动」；发消息时也会先自动拉起再发 | `LibraryStore.sendAIMessage()` |
| 上次崩溃留下孤儿服务 | 退出时一并收掉；只收「父进程是本 App 或已成孤儿」的进程，不会误杀你另外安装的 Ollama | `LocalLLMRuntime.stopServer()` |
| 重复启动 App | 新实例发现已有实例就直接退出，**不会**停掉正在用的服务 | `LumaAppDelegate.applicationWillTerminate` |
| 删除已下载 | 设置里点「删除已下载」→ 确认 → 停服务 + 删运行时 + 删模型库 + 删下载缓存 + 关开关 + 清空助手里的模型名 | `LocalLLMRuntime.uninstall()` |

注意：删除不会碰你自己通过 Homebrew / 官网安装的 Ollama，也不会删除图库里的照片或元数据。

## 2. 五个档位：什么时候用哪个

设置页档位下方会直接显示「什么时候用」；点旁边的 `?` 可以看完整对照。鼠标悬停在档位选择器上也有同一份提示。

| 档位 | 适合 | 速度 | 内存 | 可看图 |
|---|---|---|---|---|
| Qwen2.5 1.5B | 短问答、起名、文件名字段整理这类纯文本小任务 | 最快：一句话 1–3 秒 | 约 1.5 GB | 否 |
| Qwen3-VL 4B（默认） | 日常主力：对话、照片理解、界面截图识别、助手工具调用 | 较快：看图 5–15 秒 | 约 4 GB | 是 |
| Qwen2.5-VL 3B | 结构化输出与事件抽取：只回短 JSON、要求快 | 快：短输出 3–8 秒 | 约 3 GB | 是 |
| Qwen3-VL 8B | 复杂整理、多步工具调用、长上下文总结；看细节更准 | 较慢：10–40 秒 | 约 8–10 GB | 是 |
| Gemma 3 4B | 非 Qwen 备选：换一种写法、对比结果 | 中等：5–20 秒 | 约 4 GB | 是 |

选择建议：

- 只是聊天、批量起名、短文本整理 → 1.5B，快且省内存。
- 要在助手里面看图、批量整理照片 → 4B（默认档）。
- 整库多步操作、上下文很长 → 8B，但单次可能要几十秒。
- 想对比不同模型的答案 → Gemma 3 4B。

切换档位会自动下载对应模型；旧档位文件不会自动删除，可在「删除已下载」里一起清掉。

## 3. 十三个「一次性 AI 辅助」

它们和助手对话是两条独立通道：

- 不带工具、不带历史、不写对话记录；
- 只由用户点按钮触发，不后台偷跑；
- 同一时刻只跑一个请求（本机只有一个推理进程）；
- 只发送文本（统计数字、地点、日期、场景标签、候选片名、日志尾部），**不发送照片**；
- 失败只影响这一个功能，界面保留原有规则结果。

档位分配规则：

- **纯文本小任务**（体检解读、起名与旁白、分享文案、关键词补全、搜索改写、电视清洗、帮助问答、日志摘要、关键词归一化、地点补全、今晚看什么、影院系列归组）：本地档位下自动改用「已安装里体积最小」的模型（通常 1.5B）。实测同样一条起名，8B 首次 190 秒、1.5B 约 12 秒，短文本任务没必要等大模型。
- **长输出 / 长上下文**（`maxTokens` ≥ 700 或提示词 ≥ 2600 字）：自动再升一档（如 1.5B → 3B/4B），避免小模型写长 JSON 中途截断。
- **影院兜底**：用当前档位。实测 1.5B 在“该选 842 还是 none”上会保守地答 none，判断类任务需要 4B 以上。
- 云端服务不受这条规则影响，仍用你配置的模型。

### 3.1 体检 AI 解读

- 入口：图库体检页「AI 解读」卡片。
- 前置条件：体检扫描已完成（不在扫描 / 收尾中）。
- 发送内容：已检查张数、模糊张数、相似连拍组数与备选数、可腾出空间、过大视频数、截屏数、待分析数。
- 结果：三句中文（结论 / 先处理什么 / 注意事项），按报告指纹缓存，报告没变不重复请求。
- 不可用时卡片直接写原因。

### 3.2 回忆 / 旅行 AI 起名与旁白

- 入口：回忆 / 旅行卡片**右键** →「AI 起名与旁白」；旅行详情右上角也有「AI 起名」按钮。
- 发送内容：类型（按月 / 城市 / 收藏 / 往年今日 / 旅行）、张数、日期、城市名、场景标签（端侧 Vision / SigLIP 分析结果）、当前模板标题。
- **不发送 OCR 文字**（发票、证件、截图里的文字都可能敏感）。
- 结果：标题（≤12 字）+ 一句旁白；按图库持久化，切图库各存各的。
- 失败时保留原来的模板标题（如「2024年6月」「杭州之行」）。

### 3.3 影院文件名兜底

- 入口：影院顶栏状态弹层里的「AI 兜底匹配未识别」；未识别空态里也有同样按钮。
- 只处理**当前影院的未识别条目**，每次最多 6 条，可随时中断。
- 流程：按解析出的片名搜刮削源 → 取前 6 个候选（片名 / 原名 / 年份 / 类型 / 评分 / 简介片段）→ 模型只能在这些候选里选一个，或回答 `none`。
- 模型返回 `none` 时不写回，交给你手动匹配；写回只改元数据与海报，不移动、不改名、不删除视频。
- 规则打分（片名相似度 + 年份 + 类型）优先级不变：能匹配上的不会走 AI。

### 3.4 分享文案 / 朋友圈文案

- 入口：查看器（窗口内或全屏）右上角「⋯」→「AI 写分享文案」。选中多张时按选中算，否则按当前这一张。
- 发送内容：张数、日期区间、城市、端侧场景标签、已有标题与关键词；不发送照片，也不发送 OCR 文字。
- 结果：3 条文案（朋友圈 / 小红书 / 极简），在面板里逐条复制或一键复制全部。
- 纯文本任务，用已装最轻档；不可用时入口置灰并给出原因。

### 3.5 中文关键词 / 标题补全

- 入口：查看器「⋯」→「AI 补全关键词与标题」；系统图库与网盘只读，入口不出现。
- 发送内容：最多 6 张照片的文件名、日期、城市、端侧标签、OCR 前 40 字、现有标题。
- 结果：每张给 1 个标题（≤12 字）+ 3–6 个关键词，先列在面板里，默认全选，可逐条取消。
- 只有点「写入图库」才会落盘：标题写进 `title`，关键词合并进 `keywords`，同批只记一次撤销。
- 模型只负责措辞，写回走现有 `save()` / `recordUndo`，与手动编辑同一条路径。

### 3.6 搜索框自然语言 → 过滤器

- 入口：顶栏搜索框有内容时出现的闪光按钮。
- 发送内容：整句搜索词（例如「帮我找去年在海边拍的狗」）。
- 结果：改写成 App 已支持的检索语法（时间词 / 类型词 / 收藏 / 名词），直接写回搜索框，由 `SearchQueryParser` 转成真正的筛选条件。
- 改写失败会保留原句，不阻塞搜索；本地档位下完全离线。

### 3.7 电视 M3U 频道清洗与归类

- 入口：网络电视 › 频道页顶栏「AI 清洗」。
- 范围：优先当前聚焦源，其次页内源筛选，最后所有启用的源；每批 50 个频道，最多 8 批。
- 发送内容：每个频道的「序号｜台名｜分组」，不含流地址。
- 结果：只改台名（去掉高清 / 4K / 线路后缀，央视统一成 `CCTV-1 综合`）与分组（央视 / 卫视 / 地方 / 新闻 / 财经 / 体育 / 少儿 / 影视 / 纪录 / 音乐 / 港澳台 / 国际 / 其他）。
- 不改流地址、台标、回看信息；写入后整源替换并重建频道墙。想还原重新拉取源即可。
- 单批失败不中断，已处理批次照常落盘。

### 3.8 离线帮助问答

- 入口：设置 › 产品化 ›「帮助问答」。
- 内置帮助资料随 App 打包，作为系统提示词的唯一事实来源；模型只能依据它回答，覆盖不到会明确说不知道，不编造菜单名。
- 本地档位下完全离线，不检索网络。

### 3.9 诊断日志摘要

- 入口：设置 › 产品化 ›「总结最近日志」。
- 读取 `~/Library/Logs/Luma/diagnostics.log` 最近 300 行，先脱敏（家目录换成 `~`、`sk-…` 与 `Bearer …` 打码、超长行截断），再交给模型。
- 结果：三段中文（主要问题 / 可能原因 / 建议操作），可复制；不替代「导出诊断报告」。

### 3.10 关键词归一化

- 入口：关键词管理面板右上角「AI 整理词表」。
- 发送内容：当前范围出现次数最多的 120 个关键词与计数，不发照片。
- 结果：若干组「canonical + variants」，同义词 / 繁体 / 错别字合并，`IMG_1234` 这类垃圾词 canonical 留空表示删除。
- 面板里逐组勾选后才写入，同批只记一次撤销；读只读范围时不提供入口。

### 3.11 地点补全

- 入口：查看器「⋯」→「AI 补全地点」。
- 只挑「没有定位、但 OCR 有文字」的照片（最多 8 张），发送日期与 OCR 前 120 字。
- 结果：城市 + 具体地点；没把握的照片模型会跳过。确认后写 `placeCity` / `placePOI`，不写省份与 GPS。

### 3.12 电视「今晚看什么」

- 入口：网络电视 › 夜航页顶部「AI 今晚看什么」。
- 发送内容：当前节目单里最多 16 档候选（时间｜频道｜节目名｜类型）与追剧中的节目名。
- 结果：3 条「时间｜频道｜节目名｜一句理由」；只依据候选，不编造节目。

### 3.13 影院系列归组

- 入口：影院顶栏状态弹层「AI 系列归组」。
- 电影：把已识别、尚无 TMDB 合集归属的电影按系列分组（至少 2 部），写入本地合集（负数合集 ID）与一句简介；合集详情页在没有 TMDB 简介时展示这一句。
- 剧集：未识别的卡片只差「第二季 / Season 2」这类后缀时，把标题并回同一个剧名，让 `seriesKey` 合成一张卡。
- 只改元数据，不移动 / 不改名文件；重新刮削或手动匹配仍可覆盖。

### 3.14 什么时候不可用

这些功能共用同一套判断（`AIAssistCenter.availability`）：

1. 没配置模型 → 「先在设置 › 助手或本地模型里配置一个模型」；
2. 选了本地档但服务没起 → 「到设置 › 本地模型点启动服务」；
3. 本地服务在跑但当前档位模型没下载 → 提示未下载；
4. 助手正在回答 → 「等这一轮结束再试」（避免抢同一块 GPU）；
5. 本地模型是否支持看图不影响这三个功能：它们只发文本。

云端模型同样适用：只要服务地址、模型名和 Key 齐全就能用。

## 4. 配置文件字段

```json
{
  "version": 6,
  "runtime": { "release": "v0.40.19", "bytes": 189225505, "urls": ["…"] },
  "parameters": { "num_ctx": 32768, "num_predict": 2048, "temperature": 0.7, "top_p": 0.8, "top_k": 20 },
  "defaultModel": "luma-qwen3vl:4b",
  "models": [
    {
      "id": "luma-qwen3vl:4b",
      "title": "Qwen3-VL 4B",
      "detail": "推荐：能看图，中文对话明显更强",
      "when": "日常主力：对话、照片理解、界面截图识别、助手工具调用",
      "speed": "较快：看图 5–15 秒",
      "memory": "约 4 GB，推荐的默认档",
      "template": "builtin",
      "parameters": { "num_ctx": 24576 },
      "files": [
        { "file": "…Q4_K_M.gguf", "bytes": 2497281664, "urls": ["…"] },
        { "file": "mmproj-…-F16.gguf", "bytes": 836180256, "urls": ["…"] }
      ]
    }
  ]
}
```

- `parameters`：写进 Modelfile 的 `PARAMETER`。`num_ctx` 太小会报 `exceeds the available context size`；本机 11.8 GB 统一内存时 Ollama 默认只给 4096。
- `template: "builtin"`：视觉模型必须用 GGUF 自带模板，否则图片 token 拼不进提示词。
- `when` / `speed` / `memory`：只用于界面提示，不影响注册参数。
- `files` 第一个是语言模型，第二个（可选）是视觉投影器；`bytes` 必须与真实文件大小一致，否则分片下载校验会失败。

## 5. 隐私与性能

- 服务只监听 `127.0.0.1:11434`，不对外暴露；不配置任何云端服务时，数据不出本机。
- 助手「发送压缩缩略图」开关控制对话是否带图；一次性辅助固定只发文本。
- 单机只有一个推理进程：助手在跑时其它入口会让路，避免两个请求抢内存。
- 8B 在 11.8 GB 统一内存机器上会挤压其它 App；日常建议 4B。
- 体检 / 起名结果有缓存，重复点击不会重复消耗算力。

## 6. 排障

| 现象 | 处理 |
|---|---|
| 报 `request (…) exceeds the available context size (4096 tokens)` | 说明模型是按默认 4096 注册的旧模型；重启 App 会自动按清单重建参数（`num_ctx 32768/24576`），无需重下 |
| 助手底栏显示「服务未启动」 | 点旁边按钮；或设置 › 本地模型 ›「启动服务」 |
| 开关是开的但模型为空 | 到设置 › 本地模型看进度；下载失败会显示失败原因 |
| 提示「当前档位的本地模型还没下载完成」 | 等下载 / 注册完成，或换一个已装档位 |
| 删除后空间没释放 | 确认点的是「删除已下载」而不是关开关；模型在 `~/Library/Application Support/Luma/Models/` |
| 日志 | `~/Library/Logs/Luma/diagnostics.log`（含「本地模型：…」「AI 辅助：…」记录） |

## 7. 助手工具与降级

### 7.1 新增的三个助手工具

一次性能力同时注册成助手工具，助手一句话就能调用；写操作仍走「写操作审批」设置。

| 工具 | 作用 | 风险 |
|---|---|---|
| `generate_share_copy` | 为 `photo_ids` 生成 3 条分享文案，只读，不弹面板 | 只读 |
| `cleanup_tv_channels` | 清洗指定源（或当前聚焦 / 全部启用源）的台名与分组 | 可逆写 |
| `make_smart_album` | 把一句自然语言翻译成智能相簿规则并保存 | 可逆写 |

智能相簿的规则会逐条校验：字段必须在 `SmartAlbumField` 内、选项必须在允许值内、日期必须是 `yyyy-MM-dd`、数字必须可解析；非法规则直接丢弃，不会留下「有规则但永远不命中」的相簿。

### 7.2 降级策略

| 场景 | 行为 |
|---|---|
| 分享文案：没配置模型 / 服务未启动 / 模型报错 | 用日期 + 城市 + 场景标签拼 3 条模板文案，面板照常打开并提示「已按标签生成模板文案」 |
| 搜索改写：模型不可用 / 报错 | 走规则简化（去掉「帮我找」「所有的」等虚词与标点），时间词与类型词原样保留 |
| 长输出 / 长上下文 | 自动升一档模型（见第 3 节档位规则） |
| 其它一次性任务 | 入口置灰并写明原因，不静默失败 |

降级的共同目标：按钮永远有结果，且结果不会伪装成模型写的。
