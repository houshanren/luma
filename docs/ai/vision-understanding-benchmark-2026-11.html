01 · Executive Summary

01先回答四个直球问题

数据来自已安装模型的本机实测；横向对比除当前模型外为公开资料，未逐项实测。
不是「最好的图像模型」，
但可以是「最懂你生活的本地图像底座」——前提是补上评测与事件层。
Q1 · 目前用的是最好的吗
不是

SigLIP 2 Base，ViT-B 级折中

256×256 输入、768 维向量、约 355 MB。同代 SigLIP2-So400m 公开报告 Zero-shot ImageNet 83.4%（256px），Base 明显更低；本轮已把 So400m 384px 转成 Core ML 实测，覆盖率与 F1 反而下降（0 标签 17.3% vs 14.8%），因此继续用 Base。选它是为了全库可跑，不是为了刷榜。

Q2 · 做过调优吗
P1 第一轮 + 代理标定

标签补齐了，阈值还差金标集

标签 208 → 249，新增 41 个轨迹标签与双语 prompt；向量重建后存量 208 条 cos ≥ 0.999。7 个新标签用 7 张图做了代理标定，其余仍是 0.085 默认值；真实图库 1,200 张已完成采样、预测与 39 张人工标注，但召回仍测不出，249 个阈值尚未全量校准。

Q3 · 有横向对比选择吗
本机实测 + 公开指标

八个方案摆在一张表上

Vision、SigLIP2-B、So400m、CLIP / OpenCLIP、YOLO11n、YOLO-World / Grounding DINO、Qwen 三档、Florence-2。SigLIP2-B、So400m 与 Qwen 三档已有本机数据；其余为论文 / 模型卡公开指标，只做方向判断，不下性能结论。

Q4 · SigLIP2 够用吗
分层回答：够 / 不够

四个判断

判断一：先补评测，再换模型。39 张人工标注已经够判断一次升级：So400m 速度过闸，但覆盖率与 F1 都下降，所以继续用 B 版——没有标注，连这个结论都给不出。
判断二：标签体系比模型精度更缺。原来 208 个标签没有覆盖亲子、戏水、古迹、高铁、生日；本轮已补 41 个，覆盖缺口从「没有」变成「有但未全量校准」。
判断三：轨迹不是视觉问题。名胜要靠 GPS + POI，人物关系要靠人脸 + 时间，事件要靠 VLM；零样本枚举地标只会产生幻觉。
判断四：本地是底线，不是卖点。人脸、儿童、票据都必须留在本机；L3 事件抽取要默认关闭、按次授权。

04 · P0 Defect

04一个让 SigLIP 静默失效的 bug

这是本轮最重要的发现：修复前所有「中文零样本」能力实际上没有生效。

现象

SigLIPEngine 始终返回 nil，所有照片静默走 Vision 回退；isAvailable 仍为 true，UI 没有任何提示。用户看到的「中文标签」其实是 Vision 的英文分类兜底。

根因

安装包 siglip2-base-coreml 的图像塔输入是 Core ML ImageType（Color，256×256），代码一直按 MLMultiArray [1,3,256,256] 传入。Core ML 报错后被 try? 吞掉：

The model expects input feature image to be an image,
but the input (MultiArray : Float32 1 × 3 × 256 × 256 array)
is of type Image.

修复

按模型描述自适应：输入为 .image 时用 CVPixelBuffer（尺寸取 imageConstraint），否则保留张量路径；新增 ImagePixelBuffer 做等比铺满缩放。

let input = model.modelDescription
    .inputDescriptionsByName["image"]

if input?.type == .image {
    // 模型包图像塔是 ImageType：
    // 传 MultiArray 会直接抛错并静默回退。
    let size = input?.imageConstraint?.pixelsWide ?? 256
    let buffer = ImagePixelBuffer.make(from: cgImage, size: size)
    provider = try MLDictionaryFeatureProvider(dictionary: [
        "image": MLFeatureValue(pixelBuffer: buffer)
    ])
} else {
    let tensor = ImageTensor.make(from: cgImage, size: 256)
    provider = try MLDictionaryFeatureProvider(dictionary: [
        "image": MLFeatureValue(multiArray: tensor)
    ])
}
修复后：同一模型输出 768 维向量，标签冒烟 7/7。由于回退结果不写 siglip2 版本标记，安装模型后这些照片会被自动重新分析。

视频 · 已接入

抽帧，而不是逐帧

10 分钟 30fps 逐帧是 18,000 次推理，不可接受；只用首帧会把黑场 / 片头当内容。当前在 5%–95% 均匀取 4–6 帧，每帧复用照片管线，最后：

  • 标签出现 ≥ 1/3 帧才保留，不足时按频次补足；
  • OCR 去重合并，保留前 2000 字；
  • 图像向量取平均后归一化，用于相似视频；
  • AVFoundation 失败时退回内置 ffmpeg。
GPS + POI · 已增强

具体景点先于街道

逆地理编码的 POI 优先级改成：

  1. CLPlacemark.areasOfInterest（外滩 / 故宫 / 西湖）；
  2. thoroughfare（街道）；
  3. name 兜底。

没有 GPS 不猜地名；坐标只到城市级时只输出城市，不编造景点。

够用

全库「这张图像什么」

5.9 ms 的单图编码、249 个中文标签、768 维向量，做场景页、关键词、相似照片、文搜图已经够。So400m 384px 已实测：编码 87.8 ms、镜像 1.56 GB、0 标签反而增加，收益为负。

勉强

「这是哪类地方」

能分寺庙 / 教堂 / 古镇这一类，但分不出具体景点，也分不出遗址 / 城墙 / 宫殿。名胜要靠 GPS + POI，零样本枚举地标会产生幻觉。

不够

「和谁、做了什么」

亲子互动、同行人、事件、情绪，视觉编码器不负责。需要人脸身份 + 时间聚类 + 本地 VLM 输出 {activity, participants, setting, mood}。

如果只升一档：先做 30–50 个轨迹标签 + 中英双语 prompt + 阈值校准——本轮已完成 41 个。So400m 已按闸门测过，未通过。
如果要做事件：Qwen2.5-VL 3B / Qwen3-VL 4B / 8B 均已装：同 12 张 JSON 12/12，中位 4.57 / 5.14 / 10.04 s。4B 动作描述明显更细，是当前默认；三档置信度都不可信，只用于活动 / 场景 / 情绪候选，不用于「和谁」。

金标集

  • 规模：1,200 张（dev 300 / test 900），按 12 维分层，每维约 100 张。

09 · Risk & Boundary

09哪些事不能做，哪些话不能说

轨迹理解越深，隐私与幻觉风险越高。
隐私

人脸与儿童

全链路本地。人脸聚类与儿童照片属于敏感数据，L3 必须默认关闭、按次授权、结果只写本机。

幻觉

地标名称

没有 GPS 时只输出类别（寺庙 / 教堂 / 古镇），不输出具体景点名。相似建筑不等于同一地点。

敏感信息

票据与证件

OCR 文本进入搜索索引，需要可见的清除入口（已有「清空识别结果」）。

性能

与播放争抢

Vision OCR 占单张 70%+；与浏览 / 播放同时进行时会争抢 ANE / GPU，需要限流与可暂停。

许可

模型与体积

SigLIP2 与 So400m 均为 Apache-2.0；So400m 转换版 1.56 GB（图 854 MB + 文本 709 MB），分发前需确认转换链来源。

漂移

分布变化

截图、社交下载图、AI 生成图会拉低阈值有效性；金标集需每半年补样。

标定

代理 ≠ 校准

41 个新标签里只有 7 个在 7 张图上调过阈值，其余仍是 0.085；小样本会把阈值带偏，发布前必须用金标集复核。

融合

不要过度解读

「亲子时光」只表示画面里有亲子线索，不代表关系质量；文案保持「画面里常见」，不写「他很幸福」。

隐私

轨迹只用已命名人物

未命名人脸聚类不进入轨迹片段；所有融合结果只存本机，不上传，不回写系统「照片」。
