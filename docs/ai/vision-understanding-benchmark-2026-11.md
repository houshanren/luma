# 本地图像理解能力档案（2026-11）

> 范围：拾光在本机完成的图像理解链路，包括场景 / 物体标签、图内文字、条码、人脸与姿态、构图、票据 / 证件、图像向量与相似检索；视频只覆盖 4–6 帧抽帧后的视觉标签聚合。
> 不包含：云端大模型、网络资源封面、视频音频与故事级理解。
> 结论只以当前代码、当前模型包和本机实测为准；公开资料用于横向参考，均标注来源。

## 0. 结论摘要

1. **当前不是「最强」，是端侧折中。** 线上使用的是 SigLIP 2 **Base（ViT-B 级）** Core ML 版本：256×256 输入、768 维向量、约 355 MB，单张图像编码实测 **5.9–6.3 ms**（M5，warm）。同代 So400m 在公开报告中 Zero-shot ImageNet 可达 **83.4%（256px）**，Base 明显更低；本轮已用公开 384px Core ML 转换在真实图库实测 So400m，**速度过闸（p95 91 ms）但精度与覆盖率不过闸**（0 标签 17.3% vs 14.8%，样本内校准 F1 0.788 vs 0.961），因此继续用 Base（§7.10）。
2. **发现并修复了一个会让 SigLIP 静默失效的缺陷。** 模型包的图像塔输入是 Core ML `ImageType`，而代码一直传 `MLMultiArray`，`prediction` 每次抛错并被 `try?` 吞掉，结果全部回退到 Apple Vision 分类。修复后同一模型在公开样例上的 top-6 标签抽检为 **7/7**。
3. **P1 轨迹标签已落地：208 → 249。** 新增 41 个标签，覆盖亲子、戏水、古迹、高铁、生日、夜市等此前完全缺失的维度；新增标签使用 **2 条英文 + 2 条中文** 双语 prompt，向量已按「prompt 平均后归一化」重建，存量 208 条向量与旧文件 cos ≥ 0.999。
4. **阈值做了第一轮代理标定，但还不是金标集校准。** 用 7 张公开样例（含正负样本划分）为新标签给出建议阈值，7 个标签上调到 0.093–0.111，其余保持 0.085；这只能排除「已见数据上的明显误报」，不能替代 1,200 张金标集。
5. **GPS / 人脸 / 时间融合已落地第一版。** 新增 `TrajectoryFusion`：视觉标签 → 活动（亲子时光 / 海边戏水 / 古迹游览 / 美食…），再按「天 + 地点」聚成轨迹片段，并把已命名人物挂到活动与片段上；地点详情新增「这里的活动」「轨迹片段」两张卡。
6. **仍没到「轨迹级理解」。** SigLIP2 负责「这张图像什么」，融合层负责「哪天、在哪、和谁、像是在做什么」；但「为什么、心情、故事」仍需要 L3 本地 VLM。So400m 仍未下载与实测（等人工金标集证明收益）；Qwen 三档已做 12 图对比，事件 F1 尚未人工核对。
7. **单靠 SigLIP2 不够的判断不变。** 它擅长全库打标与语义检索，不负责关系与事件。三层结构仍是正确路径：L1 全库向量标签 → L2 地理 / 时间 / 人脸融合（已落地）→ L3 本地 VLM 事件抽取（待评估）。
8. **真实图库审计给出量化边界。** 在 10.2 万张图片 / 约 3.6 万条视频的图库上抽 1,200 张：61.1% 有「和谁」、57.1% 有「做了什么」、43.3% 有 GPS，三者同时仅 **28.1%**；POI 反查 14/20 命中具体景点；但场景 / 文档 / 服饰明显欠触发（天空 7 vs Apple 220、文档 59 vs 408、衣服 6 vs 313），14.8% 照片无任何标签。先修欠触发与视频评测，再谈 So400m。
9. **P2.5 已落地：Apple 分类器补齐欠触发。** 系统 Vision 分类器映射成中文标签并合入照片分析，截图再加「屏幕比例 + 文字 + 无相机信息」兜底；分析版本先升到 `siglip2-v3`，随后按 A/B 结果改成「仅 SigLIP 标签 < 2 时补」并升到 `siglip2-v4`（见第 12 条）。按同一批 1,200 张回放，0 标签照片 **178 → 25**，天空 7→201、文档 59→340、截图 101→288。全量合入时 39 张人工标注上的预测接受率从 0.753 降到 0.579；门控后 0.705，再对 7 个已证实过触发的标签做定向阈值修正后升到 **0.780**（单信号 **0.840**，见 §7.13）。
10. **40 张人工标注给出第一份真实精度。** 39 张完成标注（111 个标签、50 种、7 张判为「无合适标签」）：SigLIP 的预测标签接受率 **P = 0.753**（110 TP / 36 FP），P2.5 并集为 **0.579**（多 44 个被拒标签）。因为标注页只能从模型给出的标签里勾选，召回恒为 1，本轮能测的是精度而不是 F1。分标签看：人物 23/24、亲子互动 9/9、儿童 6/6、旅游 6/7 站得住；夜宵 0/3、天台 0/3、抱孩子 1/4、民宿 0/2、团建 0/2 的过触发被证实。**这 7 个过触发标签已在 §7.13 做定向阈值修正，单信号 0.753 → 0.840、门控 0.705 → 0.780。**
11. **Qwen3-VL 明显强于 Qwen2.5-VL，但 8B 要吃满内存。** 同一批 12 张、同一提示词：3B 中位 4.57 s / 占用 2.92 GB，4B 5.14 s / 4.47 GB，8B 10.04 s / 6.63 GB，JSON 均 12/12。4B/8B 的活动描述更具体（「溪边打卡」「翻土耕作」「婴儿玩线」vs 3B 的「拍照」「田间劳作」「玩线」），但置信度全部顶到 0.95，不能当校准值用。8B 在 16 GB M5 上把上下文开到 16384 时单张 2 分 30 秒后返回 500、Ollama 服务随即退出；8192 下稳定。
12. **Apple 第二信号已改成门控：只在 SigLIP 标签 < 2 时启用。** 同一批 1,200 张 + 39 张标注上的 A/B：0 标签率全量合入与门控都是 **2.1%（25/1200）**，而 39 张接受率从全量的 0.579 回到 **0.705**（SigLIP 单信号 0.753）。也就是说覆盖率一分没丢，误报回收了 12.6 个点。再叠加 §7.13 的 7 个标签定向阈值修正，最终为 **门控 0.780 / 单信号 0.840，0 标签 26/1,200（2.2%）**。分析版本升到 `siglip2-v4`，存量库会重扫（§7.11）。

## 1. 系统构成

```
原图
 └─ 解码：ImageIO 生成 1200px 缩略图（不持有文件映射，规避 SIGBUS）
     ├─ SigLIP2 ImageEncoder（256×256，768d）→ 中文标签 + 图像向量
     ├─ Apple Vision 分类器（第二信号，p50 17 ms）→ 补天空 / 文档 / 截图 / 服饰等欠触发
     ├─ YOLO11n（640×640，COCO 80 类，conf ≥ 0.4）→ 主体补充（最多 4 个）
     ├─ Vision：OCR（accurate，zh-Hans + en-US，语言纠正）
     │          条码 / 二维码（全 symbology）
     │          人脸矩形 + 人体姿态 → 构图标签
     │          文档分割（面积 ≥ 15%）→ 裁切后二次 OCR
     └─ 规则：发票 / 身份证校验、证件照启发式、截图启发式、组内限额、去重、版本标记
          ↓
     analysis（labels / text / feature）→ 场景页、关键词、智能相簿、搜索、相似照片
          ↓
     TrajectoryFusion：视觉标签 + 地点 + 时间 + 已命名人物
          ↓
     活动（亲子时光 / 海边戏水 / 古迹游览…）+ 轨迹片段（哪天 · 在哪 · 和谁）

视频
 └─ 抽帧：AVFoundation 在 5%–95% 均匀取 4–6 帧（短视频 4、长视频 6）
     ├─ 失败（MKV / 特殊编码）→ ffmpeg 按同一组时间点取帧
     └─ 每帧复用照片管线 → 标签按出现频次聚合 / OCR 合并 / 向量平均
```

### 1.1 开 / 不开本地模型的行为差异

本地模型默认关闭，两个开关都在「设置 › 本地模型」；关闭只停用、不删文件。产品里有两处会直接标注：

- **设置 › 本地模型**：开关上方新增「开 / 关的区别」两行说明（图像理解 / 本地语言模型）。
- **照片信息面板 › 智能标签**：SigLIP2 关闭时注明「标签来自系统 Vision，没有 249 个中文标签与语义扩展，相似检索退回 Vision 特征」；结果来自旧版本时注明会自动补扫。

| 能力 | 开启 SigLIP2 | 关闭 SigLIP2 | 代码依据 |
| --- | --- | --- | --- |
| 画面标签 | 249 个中文标签，按阈值 + 组内限额 + top-12 输出；YOLO 物体检测也只在标签 < 2 时补 | `VNClassifyImageRequest` top-20 英文 identifier + Apple 映射出的少量中文标签（人物 / 儿童 / 文档 / 截图 / 天空 / 树…） | `PhotoIntelligence.swift` 的 `usedSigLIP` 分支 |
| 场景 / 轨迹融合 | 标签 → 活动 → 轨迹片段；1,200 张里 57.1% 能映射到活动 | 规则仍运行，但可用标签变少，活动与轨迹命中明显下降 | `TrajectoryFusion.swift` |
| 相似照片 | 768 维 SigLIP 向量 | 退回 `VNGenerateImageFeaturePrint`（2,048 维）；两种向量互不比较，混用库只匹配同一来源的照片 | `PhotoIntelligence.feature(cgImage:)`、`rankSimilar` 的维度守卫 |
| 语义搜索扩展 | SigLIP 文本塔把查询映射到 249 标签空间 | 只能关键词命中，不做同义扩展 | `SigLIPEngine.expand(query:)` |
| 分析版本标记 | 写入 `siglip2-v4`，旧结果按版本补扫 | 不写标记；重新开启后这些照片会自动补扫 | `PhotoTagCatalog.sentinel` |
| 本地语言模型（对话 / 看图 / 起名 / 诊断） | Qwen2.5-VL 3B / Qwen3-VL 4B / 8B 离线可用：助手对话与看图、体检解读、起名与文案、关键词整理、地点补全、搜索改写、频道清洗、影院兜底、事件三元组 | 助手需接云端 API；一次性任务退回规则或模板（标签与轨迹不受影响） | `LocalLLMRuntime.swift` |
| 隐私与体积 | 全本机；SigLIP2 约 355 MB，Qwen 另占 2.8–6.2 GB | 不占模型体积；Vision 仍在本机，不上传 | — |

YOLO11n 不受开关控制，但按同一个条件门控：39 张标注上，它命中的 22 个标签全部已被 SigLIP 覆盖，新增正确 **0** 个、新增错误 **12** 个；无条件合入把接受率从 0.840 拉到 0.769，门控 < 2 后为 0.827（详见 §7.14）。

## 3. 实测基线

**环境**：Apple M5（10 核），16 GB，macOS 27.0.1（26A434）；模型已安装（355 MB）。**方法**：warm start，合成图（1600×1200 / 4032×3024 JPEG），不含用户照片；计时为单次预测墙钟，取 p50 / p95。

| 阶段 | n | p50 | p95 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 解码 4032 → 1200px | 12 | 22.0 ms | 24.8 ms | ImageIO thumbnail |
| SigLIP2 图像 256² | 30 | **5.92 ms** | 6.77 ms | 修复输入类型后 |
| SigLIP2 文本 64 token | 20 | 8.23 ms | 8.50 ms | 查询时 |
| 标签匹配 208×768 | 200 | 0.06 ms | 0.09 ms | float16 向量点积 |
| YOLO11n 640² | 20 | 1.63 ms | 1.89 ms | 含 NMS 后处理 |
| Vision OCR（zh+en） | 12 | 104.4 ms | 116.6 ms | 仅 OCR |
| Vision 全量（码 / 脸 / 姿态 / 文档 + OCR） | 12 | 116.5 ms | 120.3 ms | 当前管线顺序 |
| **单张串行估算** | — | **≈146 ms** | — | 解码 + SigLIP + YOLO + Vision |

派生：约 **6.8 张/秒**；1 万张全库首扫约 **24 分钟**（不含磁盘抖动、数据库写入与照片解码失败重试）。

**视频估算**：每条抽 4–6 帧，逐帧复用照片管线，约 **0.6–0.9 秒/条**（不含关键帧读取）；1,000 条视频约 10–15 分钟。长视频不会按秒抽帧，成本与视频时长基本无关。

**模型加载**（冷）：图像塔 44 ms，文本塔 177 ms，YOLO 24 ms。

**OCR 合成图**：4 行中英混排、91 个非空白字符，CER **0.00%**（仅证明管线可用，不代表真实票据 / 手写）。

**标签冒烟**（7 张 Unsplash 公开样例，仅本地测试、未入库；人工指定期望标签，判定 top-6 是否命中）：

| 样例 | 期望 | top-6 实际（分数） | 结果 |
| --- | --- | --- | :---: |
| beach | 海边 / 沙滩 | 海边 .132 · 日出 .120 · 沙滩 .108 · 日落 .104 | HIT |
| mountain | 山脉 / 雪山 | 山脉 .123 · 全景 .116 · 雾 .112 · 日出 .108 · 云朵 .092 | HIT |
| cat | 猫 | 猫 .131 | HIT |
| dog | 狗 | 狗 .120 | HIT |
| pizza | 披萨 / 美食 | 披萨 .140 · 美食 .093 · 中餐 .087 | HIT |
| car | 汽车 | 汽车 .137 · 街道 .090 · 摩托车 .082 · 城市 .082 | HIT |
| wedding | 婚礼 / 情侣 | 逆光 .116 · 情侣 .114 · 婚纱 .111 · 花束 .103 · 婚礼现场 .094 | HIT |

命中 **7/7**。样本极小、主题典型，只能说明「链路已真正生效、方向正确」，不能当作准确率。

**249 标签复测（2026-11-28）**：标签匹配从 208×768 增加到 249×768，仍为 0.07 ms 量级；同一组 7 图 top-6 仍为 **7/7**，新增的「沙滩」在海边样例上以 0.108 进入前 3，没有挤掉原有正确标签。

**速度复测的波动**：同一台 M5 在系统负载较高时，Vision 全量从 116.5 ms 升到 143.7 ms，单张串行估算从 146 ms 升到 176 ms。**本档案以低负载基线为准，同时保留波动区间**，避免把一次测量当成固定性能。

**限制**：
- 合成图 / 公开样例不代表个人图库分布（儿童、夜景、逆光、截图、票据、多人合影、宠物特写都未覆盖）。
- 未测峰值内存、能耗、长时间批量温控降频、iCloud / 系统图库读取抖动。
- 串行管线在 4K 原图解码、网络存储上会明显慢于本表。
- OCR 只测印刷体；手写、低分辨率截图、复杂排版未测。

## 4. 缺陷与修复（P0）

**现象**：`SigLIPEngine` 始终返回 `nil`，所有照片静默走 Vision 回退；`isAvailable` 仍为 true，UI 无提示。

**根因**：安装包 `siglip2-base-coreml` 的图像塔输入是 `ImageType`（Color, 256×256），代码按 `MLMultiArray [1,3,256,256]` 传入。Core ML 报
`The model expects input feature image to be an image, but the input (MultiArray : Float32 …) is of type Image.`
错误被 `try?` 吞掉。

**修复**：按模型描述自适应——输入为 `.image` 时用 `CVPixelBuffer`（尺寸取 `imageConstraint`），否则保留张量路径；同时新增 `ImagePixelBuffer`。修复后同一模型输出 768 维向量，标签冒烟 7/7。

**影响**：修复前「中文零样本标签 / 语义向量」实际上未生效；相似照片依赖 Vision feature print 兜底，语义检索扩展仅文本塔部分可用。由于回退结果不写 `siglip2` 版本标记，安装模型后这些照片会被自动重新分析。

### 5.1 融合层：从标签到一段可读的轨迹

`TrajectoryFusion` 做三件事，全部本地、纯函数：

1. **标签 → 活动**：按优先级把标签映射成活动短语，一张照片只取第一个命中的活动，避免「海边 + 沙滩 + 戏水」重复计数。规则从具体到宽泛：生日 → 婚礼 → 音乐节 → 亲子 → 戏水 → 古迹 → 高铁 → 美食 → 运动。
2. **活动 + 人物**：把已命名的人脸聚类挂到活动上，输出「海边戏水，常与小明同框」。
3. **活动 + 地点 + 时间**：按「同一天 + 同一地点」聚成轨迹片段，输出日期、地点、主活动、照片数、同框人物与封面。没有视觉活动证据的日子直接丢弃，宁可少说。

消费端：地点详情新增 **「这里的活动」**（活动分布 + 同框人物）与 **「轨迹片段」**（最近 5 段日子），叙事句也会补一句「画面里最常见的是 X」。这让标签第一次真正进入「个人生活轨迹」的阅读路径，而不只是搜索索引。

边界：这是 L2 融合，不是 L3 理解。它不推断情绪、不解释因果、不生成故事；人物只使用用户已命名的聚类，未命名人物不进入轨迹片段。

### 5.2 视频打标：为什么是抽帧，而不是逐帧

逐帧分析一条 10 分钟 30fps 的视频是 18,000 次推理，成本不可接受；只用首帧又会把黑场、片头、菜单当成内容。当前方案是：

- **时间采样**：在 5%–95% 区间均匀取 4–6 帧；短视频 4 帧、5 分钟内 5 帧、更长 6 帧。避开片头片尾，也不会只看到同一场景。
- **抽帧实现**：AVFoundation `AVAssetImageGenerator`，带 0.25s 容差、优先近似关键帧；MKV / 特殊编码失败时退回内置 ffmpeg，按同一组时间点取帧。
- **逐帧分析**：每帧复用照片的 SigLIP2 + YOLO + Vision；不另建一条模型链。
- **聚合**：标签按出现频次保留（≥ 1/3 帧），再按频次补足；OCR 去重合并；图像向量取平均后归一化。这样「整条视频是什么」比「某一帧是什么」稳定。
- **边界**：不分析音频、不做镜头分段、不做动作识别；长视频只代表 6 个时间点，不代表全片。

后续可升级的方向：用 ffmpeg 场景切换检测替代均匀采样；对超过 10 分钟的视频按章节 / 镜头聚类；加入音频事件（掌声、音乐、海浪）作为弱标签。当前不做，因为收益需要金标集验证。

### 5.3 GPS + POI：具体景点怎么反查

已有 `CLGeocoder` 逆地理编码与内置城市库兜底。本轮把 **`CLPlacemark.areasOfInterest`** 放到 POI 优先级最高：

1. 先取 `areasOfInterest`（「外滩」「故宫」「西湖」这类地标名）；
2. 没有再退回 `thoroughfare`（街道）；
3. 最后用 `name` 兜底。

结果写入 `photo.placePOI`，参与地点聚类、地点摘要与「名胜古迹」场景。没有 GPS 的照片不会猜地名；坐标只到城市级时，只输出城市，不编造景点。这样既提升具体景点的命中率，也避免零样本模型把相似建筑说成同一座地标。

## 7. 评测基准设计（待建）

### 7.1 金标集

- 规模：**1,200 张**（dev 300 / test 900），按 12 维分层，每维约 100 张。
- 来源：用户授权图库（主）+ 公开授权集（补稀有类）；全部去标识化，人脸不外传。
- 切片：有 / 无 GPS（30%）、截图 / 文档（20%）、夜景 / 低光（10%）、儿童 / 宠物（10%）、多人（≥3 脸，10%）。
- 标注：3 人双盲，20% 双标；标签 5–12 个 / 图 + 事件三元组 + OCR 文本 + 地点；Krippendorff α ≥ 0.80，分歧仲裁。
- 版本：标签目录冻结版本号；test 集每个模型版本只跑一次，防止调参泄漏。

### 7.2 指标

| 能力 | 指标 | 说明 |
| --- | --- | --- |
| 标签 | micro / macro P、R、F1 @top-8；虚幻标签率 | 分组后计算；场景 / 人物 / 食物 / 交通分切片 |
| 检索 | 文搜图 Recall@10 / mAP@20；图搜图 Recall@10 | 同事件 / 同地点切片 |

### 7.4 金标集流水线（已落地，数据待标注）

工具在 `Tools/vision_bench/`，分四步：

1. **采样 1,200 张候选**：`goldset_sample.swift`
   - 从指定照片目录递归读取 EXIF / GPS / 尺寸；先抽 4 倍候选池，再算亮度与人脸，最后按「GPS × 夜景 × 合影 / 单人」分层抽样，并单独切出截图 / 文档。
   - 只输出路径与待标注字段，不复制原图、不上传；人脸只用于统计切片，不保存特征。
2. **人工标注**：在 `goldset.json` 的 `labels` 里填 **标签 id**（如 `sandy_beach`）、`text` 填 OCR 金标、`event` 填事件三元组。支持用标题代替 id，评测脚本会自动映射。
3. **跑预测**：`vision_predict.swift` 对每张图输出 249 个标签分数与 top-12，和 App 使用同一套图像塔 / 标签向量。
4. **算指标 / 校准 / A-B**：`goldset_eval.py`
   - `eval`：micro / macro P/R/F1、按切片（GPS / 人脸 / 光照 / 月份 / 文档）、bootstrap 95% CI、per-tag CSV。
   - `calibrate`：对 249 个标签逐个扫阈值；有正样本时在精度下限内选 F1 最高；无正样本时抬到已见负样本之上，避免「标签没出现却一直误报」。
   - `compare`：两份预测（如 Base vs So400m）做配对 bootstrap，输出 micro F1 差值与 95% CI；区间跨 0 就不换模型。

**39 张人工标注**：

| 方案 | P | R | F1（micro） | micro F1（样本内校准） |
| --- | ---: | ---: | ---: | ---: |
| SigLIP2-B 256 | 0.753 | 1.000 | 0.859 | **0.961** |
| So400m 384 | 0.677 | 0.764 | 0.718 | **0.788** |

- 同阈值下 So400m 漏掉了 26 个人工接受的标签（上半身 2、书页 2，汽车 / 房屋 / 中餐 / 证件照等各 1），并新增 40 个被拒标签。
- 样本内重新校准阈值后仍然落后（macro 0.573 vs 0.965），说明问题不是「阈值没调」，而是这批中文标签上的可分性没有变好。

**闸门结论**：

| 条件 | 结果 |
| --- | --- |
| 标签 macro-F1 提升 ≥ 5 个点 | **不通过**（样本内校准 0.573 vs 0.965） |
| p95 ≤ 250 ms | 通过（90.9 ms） |
| 峰值内存 ≤ 1.2 GB | 无法用 RSS 准确度量（权重走 GPU/ANE 映射，宿主 RSS 仅 +24 MB）；磁盘 +1.2 GB，冷启动 11.9 s，按「体积可接受」一并记为不通过 |
| 结论 | **不升级默认模型，继续用 SigLIP2-B 256** |

**口径与偏差**（必须一起读）：

1. 39 张金标是在**看着 B 版预测**的情况下勾选的，天然对 B 版有利；So400m 的召回 0.764 被低估。
2. 文本塔是第三方 8-bit 转换，与官方 fp32 存在小差异（模型卡自报余弦 0.996–0.9998）；要彻底定论应改用官方 PyTorch 文本塔重算标签向量。
3. 但 1,200 张「同阈值覆盖率下降 + 0 标签增加」不依赖标注方式，是独立证据；结合速度 12×、体积 4.4×、冷启动 4×，当前没有升级理由。
4. 若日后要做「高精度可选档」，先补盲标集（≥200 张）与官方文本塔，再重跑本节的四张表。

#### 7.11 Apple 第二信号门控 A/B：只补 0–1 个标签的照片（2026-11-28）

**动机**：39 张标注已经证明全量合入 Apple 会把接受率从 0.753 拉到 0.579（多 44 个被拒标签）。但 Apple 的价值恰恰在「SigLIP 什么都没给」的照片上，所以把合入条件收窄成「SigLIP 标签数 < N 才补」，看能否只保留收益。

**做法**：`p25_union.py` 新增 `--gate-below N`，按 `siglip.tags.count`（阈值 + 组内限额 + top-12 之后的数量，与 App 一致）决定是否映射 Apple 标签。三档在同一份 1,200 张 predictions 上离线重算：

| 方案 | TP | FP | 39 张 P | 1,200 张 0 标签 | 平均标签/张 | 注入标签数 | 被跳过照片 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| SigLIP 单信号 | 110 | 36 | 0.753 | 178（14.8%） | 3.96 | — | — |
| 全量合入（v3 线上） | 110 | 80 | 0.579 | **25（2.1%）** | 5.15 | 1,497 | 0 |
| 门控 < 2（v4 采用） | 110 | 46 | **0.705** | **25（2.1%）** | 4.38 | 508 | 869 |
| 门控 < 1 | 110 | 43 | 0.719 | 25（2.1%） | 4.21 | 297 | 1,022 |

**结论**：

1. **0 标签率一分没丢。** 0 标签照片本来就属于「SigLIP 标签数 < 2」，因此三档门控的 0 标签数完全相同（25/1,200），覆盖率收益全部保留。
2. **精度回收 12.6 个点。** 39 张接受率 0.579 → 0.705，离单信号 0.753 只差 4.8 个点，被拒标签从 80 个降到 46 个。
3. **选 < 2 而不是 < 1。** `<1` 再多 1.4 个点，但只覆盖「SigLIP 一个标签都没有」的照片（297 个注入 vs 508），而「只有 1 个标签」正是最需要第二信号补场景 / 文档的情况；用 1.4 个点换掉 211 个标签的补充不划算。
4. 三档的 TP 都是 110、召回都是 1.000——门控只删误报，不碰模型已经给出的标签。

> 上表是阈值修正前的 A/B。§7.13 再对 7 个已证实过触发的标签提高阈值后，门控为 **110 TP / 31 FP（P 0.780）**、单信号 0.840，0 标签 26/1,200。

**落地**：`PhotoIntelligence.swift` 里 Apple 映射调用改为 `if siglipTagCount < 2`；版本标记升到 `siglip2-v4`，存量库会自动重扫。`AppleVisionTagMapper` 规则表未改，`p25_union.py` 必须与它同步。

**口径与偏差**：39 张仍是非盲标注（看着 v3 预测勾选），对 Apple 有利；所以 0.705 更可能是上界。权威数字要等 `docs/ai/goldset-200/` 的 200 张盲标完成（标注页已加 `--blind`，标完才展开预测）。0 标签率与平均标签数只依赖分数与阈值，不受标注方式影响。

#### 7.12 三份待人工判分的评测集（2026-11-28）

三份数据都已生成、页面都能直接打开，缺的是人工判分。它们的共同目的：把「模型看起来不错」换成可引用的数字。

**1）200 张盲标（测真实召回 + 统一校准阈值）**

- 做法：`label_sheet.py --target 200 --blind --exclude-labels docs/ai/goldset-40/labels.json`。分层规则与前 40 张一致（GPS / 人数 / 夜景 / 零标签 / 16 个高价值标签覆盖），已排除前 40 张，避免与非盲标注混在一起。

**2）150 条候选事件（Qwen3-VL 4B 三元组 F1）**

- 做法：`qwen_events.py run --limit 150`，候选事件即分层抽出的照片，提示词固定输出 `{activity, participants, setting, mood, confidence}`；模型 `luma-qwen3vl:4b`、`num_ctx=8192`、`num_predict=128`。
- 结果：**150/150 JSON 合法**，中位 3.9 s、最慢 4.64 s；活动分布以「湖边散步 6、家人聚餐 3、游客合影 3、婚礼现场 / 仪式 3」为主，没有明显退化成单一泛词。
- 判分：核对页对三个字段分别点「对 / 错」，错可写正确值。口径：字段准确率 = TP/(TP+FP)；三元组 F1 = 三条字段全对的照片占比（每条事件模型都给一个三元组、人工给一个判定，漏判与误判合并）。
- 打分：`python3 Tools/vision_bench/qwen_events.py score --out docs/ai/qwen-events --review docs/ai/qwen-events/review.json`，会输出字段 P/R/F1、三元组完全正确率与错误样例（模型值 vs 应为值）。

**3）120 条视频金标（3.6 万条视频的第一份证据）**

- 判分与评测：盲标页导出 `video_labels.json` 后，用 `goldset_eval.py merge` + `eval`（金标 `docs/ai/video-gold/video_goldset.json`、预测 `docs/ai/video-gold/video_predictions.json`）即可得到与图片同口径的 P/R/F1。

**产物**：`docs/ai/goldset-200/`（200 张盲标页 + 缩略图）、`docs/ai/qwen-events/`（150 条事件 + `results.json` + 核对页）、`docs/ai/video-gold/`（120 条 × 5 帧 + `items.json` + 标注页 + 视频级 predictions）。三份合计约 100 MB，主要是缩略图与帧图。

#### 7.14 YOLO 的边际贡献：新增召回 0，新增误报 12（2026-11-28）

**动机**：YOLO11n 一直无条件往标签里补最多 4 个物体，但从未测过它相对 SigLIP 多给了什么。用户问「YOLO 要不要升级」，先测边际贡献，再谈升级。

| 方案 | TP | FP | P | 相对 SigLIP |
| --- | ---: | ---: | ---: | ---: |
| SigLIP 单信号（阈值修正后） | 110 | 21 | **0.840** | — |
| SigLIP + YOLO（改前线上做法） | 110 | 33 | **0.769** | −7.1 个点 |
| YOLO 仅在 SigLIP 标签 < 2 时补（改后） | 110 | 23 | **0.827** | −1.3 个点 |

- **召回收益为 0**：YOLO 命中的 22 个标签全部已经在 SigLIP 结果里，没有一条是 SigLIP 漏掉、YOLO 补对的。

- 因此「升级 YOLO」是错方向：更大的 YOLO 只会把同一批误报检得更自信。检测框先留着（以后做主体裁切），但不再无条件写进标签。

**落地**：`PhotoIntelligence.swift` 的 YOLO 调用从 SigLIP 分支里移出，改为 `if siglipTagCount < 2`，与 Apple 第二信号共用同一个门控；分析版本仍是 `siglip2-v4`，存量库重扫后生效。

**口径**：39 张样本内，且 COCO 的猫 / 狗 / 汽车等类别在这批图里出现得少；如果 200 张盲标显示 YOLO 能补回 SigLIP 漏掉的物体类标签，再重新评估门控阈值。

**产物**：`Tools/vision_bench/yolo_probe.swift`；输出格式 `<id>.jpg<TAB>标签1,标签2` + 一行耗时。

## 9. 风险与边界

- **隐私**：全链路本地；人脸聚类与儿童照片属于敏感数据，L3 必须默认关闭、按次授权、结果只写本机。
- **地标幻觉**：零样本模型可能把相似建筑说成具体景点；没有 GPS 时只输出类别（寺庙 / 教堂 / 古镇），不输出具体名称。
- **OCR 敏感信息**：票据 / 证件文本进入搜索索引，需要可见的清除入口（已有「清空识别结果」）。
- **模型许可与体积**：SigLIP2 Apache-2.0；So400m 更大，需确认转换链与许可证。
- **性能竞争**：Vision OCR 占单张 70%+ 时间；与浏览 / 播放同时进行时会争抢 ANE / GPU，需要限流与可暂停。
- **分布漂移**：截图、社交下载图、AI 生成图会拉低阈值有效性；金标集需每半年补样。
- **代理标定不等于校准**：41 个新标签里只有 7 个在 7 张图上被上调阈值；2026-11-28 又按 39 张标注的证据把 7 个过触发标签上调（§7.13），其中民宿被压到库内 0 触发；其余 242 个仍是手工值，正式阈值必须用 200 张盲标统一校准。
- **新标签误报**：亲子、牵手、宠物互动等「关系类」标签容易在多人合影、广告图、影视截图上误报；本轮已把包围盒类标签（牵手 / 宠物互动 / 遛狗 / 自驾 / 停车场 / 沙滩 / 纪念日）上调，但仍需 hard-negative 挖掘。
- **Apple 第二信号的偏差**：Apple 分类器粒度粗，`clothing`、`water_body` 这类泛标签会铺得很广；本轮只映射具体词，不映射泛标签。它仍不是金标：全量合入时 39 张接受率只有 0.579，已被证伪；v4 起只在 SigLIP 标签 < 2 时启用，0 标签保持 2.2%（26/1,200），接受率 0.705，叠加 §7.13 的阈值修正后为 0.780，但这仍不是准确率结论。
- **VLM 人物幻觉**：Qwen2.5-VL 3B 曾把披萨图的「无人」说成「家人」；12 图对比里同一张图三档给出「无人 / 一人 / 一名成年男性」三种答案。因此「和谁」必须继续依赖人脸聚类，VLM 只用于活动 / 场景 / 情绪候选，且默认关闭、按次授权。
- **融合层的过度解读**：活动来自标签规则，不是真正的因果理解；「亲子时光」只表示画面里有亲子线索，不代表关系质量。文案必须保持「画面里常见」这类可核查表述，不写「他很幸福」。
- **人物隐私**：轨迹片段只使用用户已命名的人脸聚类；未命名人物不进入片段。所有融合结果只存本机，不上传，也不回写系统「照片」。
