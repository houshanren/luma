1. **库内别名串人**：`fetch_xiurenwang.library_names()` 原先先写别名键再写主名键，历史遗留的 `洛璃LoLiSAMA` 别名先把键占了，coserji 里洛璃的 37 套作品被记到日本女优 LISA 名下（库里同时还有独立的「洛璃 LoLiSAMA」）。改成两遍扫：先写全部主名，再补别名，同名时主名优先。重建后洛璃独立成条（35 套），LISA 不再收中文同名作品。
2. **封面取到广告位**：`cover_of()` 只按 `logo / icon / banner` 关键词过滤，coserji 模板里的 `/wp-content/uploads/2025/01/ad.jpg` 被当成封面，相对路径还拼成了 `https:/wp-content/...`。改为先 `urljoin` 绝对化，再过滤 `/ad.jpg`、`/ads-`、placeholder / watermark；详情页缓存到 `raw/.cn_round10/{site}/articles/`，改规则重跑不再联网。
3. **标题编号冒充人名**：madouplus 只剥一层「[机构] + 日期」会留下「VOL.133」「No.240」，这些编号靠 2,018 次出现直接冲到作品数榜首。改为最多四轮循环剥离，纯编号 / 纯符号头直接丢弃；「美腿寫真」「丽丝映像甄选」这类不带括号的机构头剥掉后继续找真人名。原始 18,841 个「名字」收敛到 1,743 人。
4. **madouplus 详情页走代理挂死**：`requests` 默认读 `HTTP_PROXY`，被本机 Clash 接管后 30 秒超时也不返回，一篇都读不到（列表页因为走缓存没暴露）。抓取 Session 统一 `trust_env = False`（这些站国内直连更快），coserji / 艺图湾等老源一并受益。
5. **镜像站同套图没去掉**：madouplus 收的是秀人系内购套（30,023 篇里有约 1 万条与 xiurenwang / myxiuren 是同一套）。原去重只认 `NO.` 且有 0.72 相似度门槛，镜像站写成 `VOL.5467`、标题又多带「性感淡彩色露肩连衣短裙 海南万宁旅拍写真」一段，相似度掉到 0.45 就被漏掉（仅王雨纯一人就残留 297 条）。改为分桶只取编号（NO/VOL 同桶）+「同人物 + 同编号 + 同日期」直接合并，全库去重 59,703 → **79,970** 条；同人物同编号不同日期（如尤蜜荟 VOL.593 2021 vs 花漾 VOL.593 2024）仍是两套，不会被误并。

### F. 多图与媒体
主头像、全身、写真、作品封面、剧照、签名。建议存 URL + 本地按需缓存，不再把 base64 塞进 SQLite（当前 41MB 里 28.9MB 是头像）。

### G. 标签体系
现在只有 111 种且偏主观。需要题材、角色、服装、IP、年代、地区、平台、奖项，并做「规范名 + 中日英别名 + 分类」。

### H. 数据质量与溯源
字段级来源、更新时间、置信度；497 条仅年份生日需要精度字段；地区误判（港台/大陆、华裔欧美）需要复核。

#### 结论

1. **增量估算（去重后）**：人物 +1,200 ～ +3,000；作品 +8,000 ～ +25,000；生日 +3,000 ～ +6,000；身高 +1,500 ～ +3,000；社交 ID +2,000 ～ +4,000；机构 +80 ～ +150。R18 dump 若打通，日本作品与女优档案另算。

## 5. 建议的数据结构

-- 人物档案（在 actresses 上扩列）
hobby, birth_precision, ruby, birthplace, blood_type,

## 7. 工程与合规注意

- 不要把作品图片塞进 SQLite；当前 41MB 里 28.9MB 是头像。作品封面/剧照会直接爆安装包。
- 作品表建议单独成库或运行时下载；R18 全量是十万级。
- 图片版权：R18 元数据 CC0，但封面/剧照不是；DMM API 对图片有条款。
- 反爬：JavLibrary/JavDB 有 Cloudflare/403，GitHub IP 被封。
- 社交接口有频率限制和 cookie 要求；小红书/抖音签名风控。
- 去重必须用 external_id + 生日 + 读音/别名；现有 497 条仅年份生日需要精度字段。
- 每个字段记录 source / confidence / updated_at。
