# 播放器起播等待层方案（2026-11）

> 状态：已采纳（2026-11-26），按本文件方案实现第一版。
> 实现要点：信息优先的等待层（片名 / 阶段进度 / 技术徽标）、本地与 SMB 起播点真实帧、
> 0.75 分辨率门限（不合格素材只做模糊底 + 小卡）、首帧 crossfade。
> 后续以实际使用体验再优化，不预先扩范围。

## 问题

起播等待期间用缩略图 / 海报铺满画面，观感差：

- 网络资源（如 Fofo 影院）：取剧集封面且 `quick: true`，实际是 320px 快速层，放大到全屏必糊。
  见 `VideoPlayerStage+Info.swift`（`preparePlayback`）与 `CatalogArtworkCache.image(quick:)`。
- 本地视频：起播底图是导入时生成的缩略图，最高 1200px，4K 全屏下偏软。
  见 `VideoSupport.makeThumbnail`（`maximumSize 1200×1200`）。
- 展示方式：`VideoPosterBackdrop` 用 `scaledToFill` 直接把图拉满，低分辨率被放大得更明显。

## 方案 A：继续用图，但提高质量 / 不暴露低清

1. **改展示方式**：低清图不铺满。背景用同图重模糊（模糊是刻意的），前景放小尺寸清晰卡片；或纯色 / 品牌渐变 + 标题 + 缓冲胶囊。零额外存储。
2. **换素材**：等待层不用 320px 快速层，改用原始封面（`quick: false`）、剧集剧照或条目背景图。
3. **用真实首帧**：
   - 本地 / SMB：`AVAssetImageGenerator` 在 `resumeOffset` 处现取一帧，限制到屏幕像素（如 1920 / 2560），通常几十毫秒。
   - 云端 / 网络：ffmpeg 转封装或生成首段 HLS 时顺手多输出一帧 1080p JPEG 作为 poster，几乎零额外成本。
4. **单独做「播放器海报」缓存**：按视频 id 存一张 1920 宽 poster（或按屏幕像素生成），与网格缩略图分开，纳入现有缓存上限与淘汰机制。约 150–300KB/片。
5. **分层过渡**：缩略图先出（<50ms）→ 高清帧到达后交叉淡入替换；高清不来时停在方案 1 的氛围底 + 小图。
6. **网络源特殊处理**：站点封面多为竖版小图，不适合全屏底图，直接跳过图片，用渐变 + 片名。

## 方案 B：完全不用图片

核心思路：等待层的任务是「说明正在发生什么」，不是「冒充画面」。

1. **影院风黑场 + 结构化信息**
   纯黑底，居中显示片名 / 集数 / 时长 / 年份，下方细进度条或小 spinner。
   不暴露画质，也符合观影场景的低干扰预期。

2. **分阶段进度反馈**
   把现有 `Diagnostics` 的阶段变成用户可读的短文案与进度：
   `解析地址 → 探测片源 → 建立首段 → 即将播放`。
   有进展感比一张静态图更能缓解等待焦虑。

3. **技术徽标行**
   显示解析出的规格：`4K · HDR10 / Dolby Vision · HEVC · 5.1 · 简中字幕`。
   既填充视觉空白，也是产品差异化信息（Netflix / Infuse 风格）。

4. **程序化视觉（零图片资源）**
   - 缓慢流动的品牌渐变（暗色 + 金色高光），Core Animation 驱动，GPU 成本极低。
   - 胶片颗粒 / 暗角 / 光晕等程序化质感，呼应影院主题，不依赖任何素材。
   - 骨架屏式布局：先把标题、控制条、进度条骨架画出来，再填充真实状态。

5. **播放器 UI 前置**
   直接显示半透明控制条、大播放按钮、时间轴与音量，等待过程就是播放器 UI 的一部分，而不是一张独立插画。

6. **声音先行（可选）**
   允许音频先起播、画面保持过渡层，配上轻量音频波形或「正在载入画面」提示。
   适合缓冲慢但音频已就绪的场景，需评估用户困惑成本。

7. **承接上一段的最后一帧**
   连播时用上一集结尾帧做过渡（本质是视频帧，不是缩略图），跨集切换几乎无黑屏。

8. **缩短「无内容窗口」本身**
   预热下一集、缓存首段、起播点就近取帧——最彻底的「占位方案」是让占位时间趋近于零。
   现有 `takePrewarmedCinemaStream` / `playFromCompleteCache` 已经在这条路上。

## 按来源组合（讨论稿）

判断轴：**可用素材质量 × 首段耗时 × 用户此刻关心什么**。
点播关心「这是哪一部」，直播关心「连上了没有」。

| 来源 | 典型耗时 | 可用素材 | 等待层组合 | 出图过渡 |
| --- | --- | --- | --- | --- |
| 图库视频（本机） | < 100ms | 不用素材（不取首帧） | 不处理：什么都不显示，直接出画面 | 无需 |
| 本地视频（SMB / 外置盘 / 下载目录） | 0.3–2s | 本地缩略图 1200px；可就地取帧 | A3 起播点真实帧（1920，`AVAssetImageGenerator`）；失败退回「模糊氛围底 + 小卡」；超过 1s 才出 spinner | 150–250ms crossfade |
| 网络视频（站点 / 网络资源） | 1–5s | 站点封面多为 320px 竖图；可能有 ≥720p 背景图 | B1 黑场 + 片名/集数 + B2 阶段进度（解析地址→探测→首段）+ B3 技术徽标；有高清背景图时改「模糊底 + 小卡」，绝不铺 320px 封面 | 首帧 crossfade |
| 网盘（115 / 阿里 / 夸克 / 百度 / WebDAV） | 1–10s | 已有云缩略图（≤900px）；远端取帧成本高 | B1 + B2（获取直链→探测→首段）+ 品牌色流动渐变；云缩略图只做小卡 / 模糊底；转码时显示「色调映射 / 去隔行 / 4K 重编码」状态 | 首段就绪后 crossfade |
| 直播 | 2–8s | 台标、EPG 当前节目；`TVPreviewCache` 480px 抓帧可做模糊底 | B1 频道名 + 台标 + 当前节目 + 线路 n/m + 「正在连接」；不用全屏图；失败给换线入口 | 首帧直接切换 |
| 回放（电视回看 / catch-up） | 2–6s | 节目名、频道、时段；可选抓帧 | B1 + B2（建立回看流）+ 节目信息；有抓帧做小卡 | 首帧 crossfade |

### 跨来源统一规则

1. **分辨率门限**：素材短边 ≥ 屏幕短边 × 0.75 才允许铺满；否则只做模糊底或完全不用图。
2. **阶段文案最多 3 段**，避免快速跳变；超过 8s 追加「仍在准备」并给取消 / 换源。
3. **首帧到达后 crossfade**，不要硬切；低清图先出时同样淡入淡出。
4. **技术徽标常驻角落**（分辨率 / HDR / 音轨 / 字幕），等待时也有信息价值。
5. **无图兜底统一**：任何来源在拿不到合格素材时，都落到 B4 的骨架 + 程序化渐变，保证不会出现低清图铺满。

## 倾向

- 网络资源与网盘：方案 B 的 1 + 2 + 3（黑场 + 阶段进度 + 技术徽标），可用 4 的流动渐变。
- 本地视频：方案 A 的 3（起播点真实帧），必要时叠 4 的 poster 缓存。
- 直播 / 回放：本质是 B 系列（频道 / 节目信息优先），可选 TVPreviewCache 做氛围底。
- 通用兜底：方案 B 的 4（骨架 + 程序化渐变）。
